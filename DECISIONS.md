# Decision register

Accepted product requirements originate from the user's request and established research conversation. Engineering conventions below are a v0.1 design baseline, not empirically validated trading rules.

| ID | Decision | Reason |
|---|---|---|
| D01 | Independent repository and VS Code workspace | Keep all HVAC work separate |
| D02 | Discovery → alert → human decision → deferred Exit Intelligence | Keep selection separate from managing a chosen position |
| D03 | FOMO-only actionable universe | Supported chain alone does not establish token tradability |
| D04 | WATCH/HIGH; quality determines frequency | Zero or multiple independent HIGHs allowed; no quota |
| D05 | HIGH is evidence priority only | No buying instruction or position sizing |
| D06 | Immutable prospective evidence and alert snapshots | Prevent hindsight and silent corrections |
| D07 | Paper/shadow validation first | No established signal edge yet |
| D08 | Observe all candidates, exclusions and failures | Reduce survivorship and selection bias |
| D09 | Trader rules are hypotheses | Anecdotes, reported P&L and filters are not validation |
| D10 | Separate Exit data, scoring and evaluation | Comparable-coin exit targets must not enter Discovery features |
| D11 | No purchases, subscriptions or execution | Current authorization is research and foundation only |
| D12 | Eventual 24/7 operation with health reporting | Silence must be distinguishable from an outage |
| D13 | Unknown/stale FOMO verification blocks actionable alerts | Fail closed; preserve internal research observations |
| D14 | No initial score weights or HIGH thresholds | Learn incremental usefulness before combining signals |
| D15 | Immutable candidate observation records | Preserve historical evidence and prevent future information from leaking into earlier decisions |
| D16 | Explicit `NO_NARRATIVE_FOUND` and `UNVERIFIED` states | Fail closed on missing evidence instead of inventing narrative or executability |
| D17 | BUNDAR is the application brand; Meme Coin Radar remains the engineering name | BUNDA + radar; retain repository, workspace and package compatibility |
| D18 | Separate frozen narrative module; preserve legacy models and research | Strong nested immutability without rewriting prior observation behavior |
| D19 | Fixed contract-linked-narrative/v1 presence/lineage rule | A cited same-subject identity + exact-contract capture + narrative observation establishes minimum research support, not quality or a prediction |
| D20 | Explicit aware occurrence/retrieval/detection/cutoff/completion timestamps | Reject late evidence, measure latency and distinguish evidence availability from completed packet availability |
| D21 | Raw scoped measurements or cited classifications with explicit rubric versions | No unsupported numeric confidence, qualitative labels, weights, HIGH/WATCH or price targets |
| D22 | Human/fixture annotations only; no LLM or live integrations in this prototype | Deterministic auditable construction, not semantic verification or a coin-quality scorer |
| D23 | CT/X is an evidence-producing layer, separate from alert policy | No HIGH/WATCH, buying recommendation, Twitter score or price prediction |
| D24 | Use timestamped/versioned literal alias registries in parser V1 | Replayable conservative extraction; unknown/new subjects remain explicit |
| D25 | Preserve target alias and address-chain ambiguity | Ticker/name is not chain+contract; no guessed token association |
| D26 | Keep subject attention distinct from exact-contract discussion | Tokenless catalysts and multi-contract narratives must stay observable |
| D27 | Preserve account metadata without reputation or independence inference | Followers/verification/popularity do not establish trader skill |
| D28 | Measure duplication/near-duplication and timing under explicit text rules | Possible noisy propagation is not proof of bots or manipulation |
| D29 | Adapter normalizes supplied official-v2 responses; no transport in V1 | No live/paid calls, costs, upgrades or uncontrolled pagination |
| D30 | Bridge CT observations only; report missing-field exclusions | Twitter activity cannot invent identity/capture/hypothesis support or force a narrative |
| D31 | Evaluate on labeled synthetic replay separately from financial outcomes | Perfect conformance does not establish real-X performance or a trading edge |
| D32 | User-confirmed local credential plus separate bounded one-shot transport | Limit actual request consumption; preserve failed attempts; no credential logs or plan changes |
| D33 | Freeze 4-attempt / 31-post / 62-resource ceiling before real capture | No automatic retries/pagination or expansion when diversity is missing |
| D34 | Human-only blank real labels, deterministic grouped development/held-out split | Prevent predictions becoming ground truth and held-out tuning |
| D35 | Preserve source receipt cutoff separately from later replay computation | Do not backdate parse completion or later engagement/account information |
| D36 | Real accuracy remains unavailable until independent labels exist | Structural bridge checks are not parser correctness or prospective readiness |

Current-market narrative similarity using only pre-decision evidence is permitted Discovery research. Historical comparable-coin target ranges, de-risking zones and exit recommendations belong exclusively to deferred Exit Intelligence.

Unresolved: current FOMO supported chains and authoritative eligibility evidence; providers and permitted access; freshness/latency budgets; runtime/storage/hosting; observation cadence; simulation notionals and fees; wallet qualification and cluster method; model thresholds; validation sample size and success criteria; alert destination. Resolve and version these before the dependent implementation or experiment. No current vendor capability is assumed from the transcript.
